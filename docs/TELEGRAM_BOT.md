# Telegram-бот @RutaCriptoSeguraBot — бесплатный PDF-гайд за подписку

Бот проверяет **настоящую** подписку пользователя на канал [@rutacriptosegura](https://t.me/rutacriptosegura) и отправляет ему PDF-гайд в личные сообщения. Все сообщения бота — на испанском. Платных функций, Premium и оплаты в этой версии нет.

## 1. Как это устроено

```
Пользователь ──/start──▶ Telegram ──webhook (HTTPS + секрет)──▶ Vercel: /api/telegram/webhook
                                                                     │
        «Verificar suscripción» ──▶ getChatMember(@rutacriptosegura, user_id из события)
                                                                     │  подписан?
                                                       да ───────────┴───────────── нет
                                                       │                              │
                                  sendMessage + sendDocument(file_id) + sendMessage    «Todavía no encontramos…» + кнопки
                                                       │
                                   Upstash Redis: только дедупликация, лимиты, file_id гайда, счётчики
```

- **Где живёт код.** Внутри сайта (Next.js 16 на Vercel): маршрут `app/api/telegram/webhook`. Отдельный сервер не нужен — для такого бота это дешевле и проще. Цена вопроса: бот зависит от деплоя сайта (откат деплоя в Vercel — одна кнопка).
- **Где живёт PDF.** Только на серверах Telegram. Вы один раз отправляете файл боту, он запоминает `file_id` и дальше рассылает по нему. PDF **не лежит** в репозитории, в `public/` и на диске Vercel, публичной ссылки на него нет.
- **Хранилище.** Vercel не хранит файлы между запросами, поэтому нужна маленькая база: Upstash Redis (бесплатного тарифа хватает на старт). Подключение — обычным `fetch`, без SDK и новых зависимостей.
- **Подписка** проверяется только вызовом Telegram `getChatMember` по `user_id` из самого события. Нажатие кнопки само по себе ничего не подтверждает. Подписанными считаются `member`, `administrator`, `creator` и `restricted` при `is_member = true`.

## 3. Что нужно сделать вручную (коротко)

1. Создать базу **Upstash Redis** и получить два значения (раздел 4).
2. Придумать **секрет webhook** — случайную строку (раздел 5).
3. Добавить **переменные окружения в Vercel** (раздел 5). Токен бота вы вводите только там — в чат его присылать не нужно.
4. Влить PR с ботом в `main` (боевой адрес) и дождаться Production Deployment (раздел 6).
5. **Включить webhook кнопкой** на временной странице `/telegram-setup` (раздел 7: ключ и выключатель в Vercel, merge, проверка, подключение, `/start`, выключение страницы). Терминал не нужен.
6. Написать боту `/id`, добавить свой ID в `TELEGRAM_ADMIN_USER_IDS`, **передеплоить** (раздел 8).
7. **Загрузить PDF** через бота (раздел 8).
8. Пройти **план тестирования** (раздел 10).
9. Только после этого — подтвердить мне переключение ссылок на сайте (раздел 11).

## 4. Redis (Upstash)

Вариант А (проще): Vercel → ваш проект → **Storage** → **Create Database** → Marketplace → **Upstash** → **Redis**, регион ближе к вашему региону Vercel, подключить к проекту. Vercel сам добавит переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN` — **именно их читает бот**. Остальные (`KV_REST_API_READ_ONLY_TOKEN`, `KV_URL`, `REDIS_URL`) бот не использует: ему нужен токен с правом записи, а read-only токен он намеренно игнорирует.

Вариант Б: создать базу на upstash.com, скопировать **REST URL** и **REST Token** и добавить их в Vercel вручную под именами `KV_REST_API_URL` и `KV_REST_API_TOKEN` (раздел 5). Имена `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` тоже работают как запасные: если заданы обе пары, берётся пара `KV_*`, а пары никогда не смешиваются.

Нагрузка: одна проверка подписки — около 15–25 команд Redis. Бесплатного лимита Upstash хватает на тысячи выдач в месяц; при росте тариф оплачивается по факту использования.

## 5. Переменные окружения

Добавляются в Vercel: **Project → Settings → Environment Variables**, окружение **Production** (для проверки на превью — ещё и Preview). Токен и секреты отмечайте **Sensitive**. Ни одна переменная не начинается с `NEXT_PUBLIC_` — они не попадают в браузер.

| Имя | Что это | Обязательно |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота из @BotFather. Если токен когда-либо попал в чат, письмо или Git — перевыпустите его в BotFather (`/revoke`) | да |
| `TELEGRAM_WEBHOOK_SECRET` | Случайная строка, которую Telegram присылает с каждым событием. 16–256 символов `A-Z a-z 0-9 _ -` | да |
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` | Доступ к Redis (раздел 4). Запасные имена: `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` | да |
| `TELEGRAM_ADMIN_USER_IDS` | Числовые Telegram ID тех, кто может загружать PDF и видеть `/estado`; через запятую | на первом деплое пусто, потом обязательно |
| `TELEGRAM_CHANNEL_CHAT_ID` | Канал для проверки подписки. По умолчанию — официальный канал `@rutacriptosegura` (адрес в `lib/bot/links.ts`) | нет |
| `TELEGRAM_GUIDE_FILE_ID` | Аварийная копия `file_id` гайда, если база потеряна | нет |
| `TELEGRAM_SETUP_ENABLED` | Временный выключатель страницы `/telegram-setup`: при значении `true` страница есть, иначе (или без переменной) её нет — ответ 404. Включайте только на время подключения | временно |
| `TELEGRAM_SETUP_SECRET` | Отдельный ключ страницы настройки: 24–128 видимых символов без пробелов, не совпадает с токеном бота, секретом webhook и токенами Redis | пока страница включена |

Секрет для `TELEGRAM_WEBHOOK_SECRET` и ключ для `TELEGRAM_SETUP_SECRET` — это случайные строки. Создайте их менеджером паролей (32 символа, без пробелов) или кнопкой «Создать ключ» на странице `/telegram-setup` (раздел 7): она работает прямо в браузере. Значения никому не показывайте и не присылайте в чат.

> Переменные окружения применяются только к **новым** деплоям. После любого их изменения: Vercel → Deployments → ⋯ → **Redeploy**.

## 6. Деплой

Бот опубликован **отдельным минимальным PR** (ветка `claude/telegram-bot-only-ybtk1k`): в нём только код бота, его тесты, скрипты и документация — ни дизайна, ни юридических страниц, ни изменений кнопок. Боевой адрес `https://crypto-education-landing-page.vercel.app` собирается из `main`, поэтому бот заработает на нём после merge этого PR и **Redeploy** (переменные окружения подхватываются только новым деплоем). Остальные изменения сайта (дизайн, юридические страницы, согласие на cookies, Telegram-ссылки) остаются в PR #2 и публикуются отдельно.

Пока webhook не включён, эндпоинт **ничего не делает**: без секрета он отвечает 401, при незаданных переменных — 503, а Telegram о нём не знает. Сам по себе merge бота не запускает: webhook включается только вручную, командой из раздела 7.

Проверка на превью до merge: переменные должны быть заданы и для окружения **Preview** (без них превью отвечает 503 — так задумано). Адреса `…-git-…vercel.app` закрыты защитой Vercel («Deployment Protection»), и Telegram до них не достучится. Для проверки в Vercel → Settings → Deployment Protection включите **Protection Bypass for Automation**, а к адресу webhook добавьте `?x-vercel-protection-bypass=<секрет обхода>`. Для боевого запуска это не нужно.

## 7. Подключение Telegram через браузер (страница /telegram-setup)

Webhook включается одной кнопкой на временной странице `https://crypto-education-landing-page.vercel.app/telegram-setup`. Терминал, Node.js и Git на вашем компьютере не нужны: всё делается в Vercel, GitHub и Telegram.

**Как это защищено**

- Страница существует, только пока в Vercel задано `TELEGRAM_SETUP_ENABLED=true`. Без этой переменной (или с любым другим значением) адрес `/telegram-setup` и серверный обработчик `/api/telegram/setup` отвечают 404, как несуществующие.
- Нужен отдельный ключ — переменная `TELEGRAM_SETUP_SECRET`. Он вводится в форму и уходит на сервер только в теле POST-запроса (не в адресе), сравнивается за постоянное время, нигде не сохраняется и не попадает в логи. Если ключ не задан, слишком короткий или совпадает с другим секретом, страница ничего не делает.
- Попытки ограничены: после 5 неверных ключей посетитель блокируется на 15 минут (даже с верным ключом), после 40 неверных за 15 минут вход закрывается для всех, и не больше 30 запросов за 10 минут с одного адреса. Счётчики лежат в Redis под хешами, адреса посетителей не хранятся.
- Все обращения к Telegram выполняет сервер. Токен бота, секрет webhook и токены Redis в браузер не попадают: в отчёте только имена переменных и «есть/нет».
- Адрес webhook зашит в коде (`https://crypto-education-landing-page.vercel.app/api/telegram/webhook`), страница не принимает произвольный адрес. События — только `message` и `callback_query`. Telegram получает ваш существующий `TELEGRAM_WEBHOOK_SECRET` как `secret_token`.
- Webhook не включается при деплое. Он включается только после нажатия «Подключить Telegram» и только если проверка прошла: токен принадлежит @RutaCriptoSeguraBot, бот — администратор канала, Redis принимает запись. Отсутствие PDF и администраторов подключению не мешает.
- Страница закрыта для поисковиков (`noindex`), не кэшируется, не открывается во фрейме, а в боевом режиме работает только с адреса `https://crypto-education-landing-page.vercel.app`.

### Шаг 1. Добавьте две переменные в Vercel

1. Vercel → ваш проект → **Settings → Environment Variables**.
2. **Add New**: имя `TELEGRAM_SETUP_SECRET`, значение — ваш ключ (24 символа и больше), окружение **Production**, включите **Sensitive** → **Save**.
3. **Add New**: имя `TELEGRAM_SETUP_ENABLED`, значение `true`, окружение **Production** → **Save**.

Ключ получите так (придумывать его не нужно):

- в менеджере паролей (Apple, Google, 1Password…): «сгенерировать пароль», 32 символа, без пробелов; или
- на самой странице: раскройте «У меня ещё нет ключа — создать его в браузере» → «Создать ключ» → «Копировать». Ключ создаётся в вашем браузере и никуда не отправляется. Для этого способа сначала добавьте только `TELEGRAM_SETUP_ENABLED=true`, дождитесь деплоя и откройте страницу (она предупредит, что ключ не задан), затем добавьте `TELEGRAM_SETUP_SECRET` и сделайте Redeploy.

Сохраните ключ в менеджере паролей, не присылайте его в чат и никому не показывайте. Переменные работают только в новых деплоях: если вы добавили их после последнего деплоя, сделайте Vercel → **Deployments** → ⋯ у последнего Production-деплоя → **Redeploy**.

### Шаг 2. Объедините PR

GitHub → **Pull requests** → откройте PR со страницей настройки → **Merge pull request** → **Confirm merge**. Vercel сам запустит Production Deployment: дождитесь статуса **Ready** (Vercel → **Deployments**).

### Шаг 3. Откройте страницу

`https://crypto-education-landing-page.vercel.app/telegram-setup`. Если там ошибка 404: в Production нет `TELEGRAM_SETUP_ENABLED=true` или после добавления переменной не сделан Redeploy.

### Шаг 4. Нажмите «Проверить подключение»

Вставьте ключ в поле «Ключ настройки» и нажмите кнопку. Страница ничего не меняет в Telegram, только читает. В отчёте семь пунктов:

| Пункт | ✓ означает | Если ✕ |
|---|---|---|
| Переменные окружения | все обязательные заданы и верного формата | в списке названо, какой нет или она неверна (значения не показываются): исправьте в Vercel и сделайте Redeploy |
| Бот | токен действителен и принадлежит @RutaCriptoSeguraBot | неверный или отозванный токен, либо токен другого бота: проверьте `TELEGRAM_BOT_TOKEN` |
| Канал @rutacriptosegura | бот — администратор канала | добавьте бота в канал администратором (права на публикацию не нужны) |
| Redis (Upstash) | запись и чтение работают | неверные `KV_REST_API_*` или токен «только для чтения» (`KV_REST_API_READ_ONLY_TOKEN` не подходит) |
| Webhook | до подключения: «ещё не подключён» (это нормально); после: «подключён правильно» | показано состояние; чужой адрес не отображается, кнопка «Подключить» заменит его |
| PDF-гайд, Администраторы бота | «не загружен», «не заданы»: это нормально на этом этапе, они нужны позже (раздел 8) | не блокируют подключение |

Кнопка «Подключить Telegram» остаётся недоступной, пока проверка не пройдена.

### Шаг 5. Нажмите «Подключить Telegram»

Сервер ещё раз проверит всё, затем задаст меню команд бота, подключит webhook и прочитает его состояние. Результат: блок «Telegram подключён» с двумя отмеченными шагами и пункт Webhook «Подключён правильно». Ключ из формы очищается. Если Telegram что-то отклонит, страница покажет причину, а webhook останется выключенным.

### Шаг 6. Проверьте /start

В Telegram откройте @RutaCriptoSeguraBot и нажмите Start. Ожидается приветствие на испанском и две кнопки: «Suscribirme al canal» и «Verificar suscripción». С аккаунта без подписки кнопка проверки отвечает «Todavía no encontramos tu suscripción». Пока PDF не загружен, подписанный пользователь увидит, что гайд пока недоступен: загрузка описана в разделе 8.

### Шаг 7. Выключите страницу

Vercel → **Settings → Environment Variables** → удалите `TELEGRAM_SETUP_ENABLED` и `TELEGRAM_SETUP_SECRET` (минимум — поставьте `TELEGRAM_SETUP_ENABLED=false`) → **Deployments** → ⋯ → **Redeploy**. Выключение вступает в силу только после Redeploy. Проверьте: `/telegram-setup` должна отвечать 404. Подключённый webhook остаётся в Telegram и продолжает работать. Для смены токена или секрета включите страницу заново тем же способом.

### Сообщения страницы

| Сообщение | Причина |
|---|---|
| «Неверный ключ настройки» | Введён не тот ключ, что в `TELEGRAM_SETUP_SECRET`, или после изменения переменной не сделан Redeploy |
| «Слишком много попыток…» | Сработал лимит попыток; подождите около 15 минут |
| «Настройка включена, но ключ не задан или недопустим» | `TELEGRAM_SETUP_SECRET` отсутствует, короче 24 символов, содержит пробел или совпадает с другим секретом |
| «Откройте страницу по адресу …» | Страница открыта не с боевого адреса |
| «Настройка сейчас выключена» | Выключатель убрали, пока страница была открыта |
| «Подключение не выполнено: сначала исправьте пункты с ошибкой» | Проверка не прошла, в Telegram ничего не менялось |
| «Меню команд бота: не удалось» или «Подключение webhook: не удалось» | Telegram отклонил запрос; webhook остался выключенным |

Для разработчиков: `scripts/telegram/webhook.mjs` делает то же из терминала. Владельцу он не нужен.

## 8. Безопасная загрузка PDF

PDF уходит с вашего аккаунта Telegram прямо на серверы Telegram. Через наш сервер файл не проходит.

1. Напишите боту `/id` — он ответит вашим числовым ID. Добавьте его в `TELEGRAM_ADMIN_USER_IDS` (Vercel), сделайте **Redeploy**.
2. В чате с ботом отправьте файл `Ruta_Cripto_Segura_Estilo_Web.pdf` **как документ** (скрепка → «Файл», не «Фото») и в подписи к файлу напишите: `/subir_guia`.
3. Бот ответит «✅ Guía guardada (main)» с именем и размером. Теперь ваш аккаунт — единственный (кроме других ID из списка), кто может менять гайд.
4. Отправьте `/guia` — проверьте полный путь (вы подписаны на канал → получите файл).
5. `/estado` покажет состояние: Redis, гайд, права бота в канале, счётчики за сегодня/7 дней/всё время.

## 11. Эксплуатация

- **Логи:** Vercel → проект → Logs, фильтр `/api/telegram`. Одна JSON-строка на событие; токены, секреты, тексты сообщений и Telegram ID не логируются (в логах только короткий псевдоним).
- **Ошибки доставки webhook:** включите страницу `/telegram-setup` на время проверки (раздел 7) и нажмите «Проверить подключение»: пункт Webhook покажет очередь и последнюю ошибку доставки.
- **Алерты администраторам:** если гайд не загружен, Telegram отклонил файл или бот потерял доступ к каналу, админам приходит сообщение (не чаще раза в час на тип проблемы).
- **Лимиты на человека:** проверка не чаще раза в 2 секунды и 40 раз в час; не более 5 выдач в сутки; не более 30 сообщений в минуту.
- **Смена токена:** BotFather → `/revoke` → новый токен в Vercel → Redeploy → страница `/telegram-setup` → «Подключить Telegram» (раздел 7). `file_id` гайда сохраняется.
- **Смена секрета webhook:** новое значение в Vercel → Redeploy → страница `/telegram-setup` → «Подключить Telegram» ещё раз (Telegram получит новый `secret_token`). Счётчики лимитов обнулятся (псевдонимы привязаны к секрету) — это безопасно.
- **Откат:** Vercel → Deployments → предыдущий деплой → Promote. Состояние бота хранится в Redis и от деплоя не зависит.

### Что хранится в Redis (персональные данные сведены к минимуму)

Имена, username и тексты сообщений не хранятся **нигде**. Telegram ID хранится только в виде необратимого псевдонима (HMAC с вашим секретом).

| Ключ | Содержимое | Срок |
|---|---|---|
| `upd:{id}`, `try:{id}` | Метка «это событие уже обработано» | 2 суток / 1 час |
| `fl:`, `vg:`, `vh:`, `lock:`, `cap:` + псевдоним | Счётчики лимитов | секунды — сутки |
| `dr:` + псевдоним | Когда впервые и в последний раз выдан гайд, сколько раз | 365 дней после последней выдачи |
| `al:{тип}` | Метка «алерт уже отправлен» | 1 час |
| `guide:main` | `file_id`, имя и размер файла, дата загрузки | пока вы не замените |
| `st:*` | Обезличенные счётчики: старты, проверки, выдачи | 100 дней по дням; итоги — без срока |

## 12. Как подключить Lava.top, Premium-канал и платные подписки позже

Бесплатный бот сделан так, чтобы платное добавлялось, а не переписывалось:

- **Платежи Lava.top** — отдельный маршрут `app/api/payments/lava/route.ts` (свой секрет, своя проверка подписи). Он записывает право доступа в Redis по тому же принципу, что и гайд.
- **Закрытый Premium-канал** — бот добавляется администратором в Premium-канал, при оплате создаёт одноразовую ссылку-приглашение (`createChatInviteLink` с `member_limit = 1`), при окончании подписки снимает доступ. Для этого понадобится хранить **настоящий** Telegram ID платящих клиентов (отдельный раздел базы, другое правовое основание — договор) — поэтому он не смешан с обезличенными данными бесплатного гайда.
- **Telegram Stars** — в `handlers.ts` добавляются обработчики `pre_checkout_query` и `successful_payment` (добавить типы обновлений в `SETUP_ALLOWED_UPDATES` в `lib/bot/setup.ts` и в `ALLOWED_UPDATES` в `scripts/telegram/webhook.mjs`).
- **Несколько гайдов:** загрузка `/subir_guia другое_имя` уже сохраняет файл под своим именем; осталось привязать имя к параметру `?start=` и кнопке на сайте.
